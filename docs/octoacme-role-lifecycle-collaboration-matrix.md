# OctoAcme — Role-to-Lifecycle Collaboration Matrix

## Purpose
Provide a quick reference for who leads, contributes, and is consulted across initiation, planning, execution, release, and retrospective activities.

## How to use
- Use this matrix during kickoff and planning to confirm ownership and handoffs.
- Treat this as a practical guide; PM and PdM can adjust for project size and risk.

## Lifecycle ownership and collaboration

| Lifecycle Activity | Primary Owner(s) | Key Contributors | Typical Handoff / Output |
| --- | --- | --- | --- |
| Problem framing, goals, success metrics (Initiation) | Product Manager, Project Manager | Stakeholder/Sponsor, UX Designer, Data Analyst, Engineering Manager | Approved one-pager with measurable outcomes and stakeholder alignment |
| Initial scope, team formation, and timeline (Initiation) | Project Manager | Engineering Manager, Technical Lead, Product Manager | Initial milestone plan and role coverage |
| Backlog, acceptance criteria, and Definition of Done (Planning) | Product Manager, Project Manager | Developers, QA/Test Engineer, UX Designer, Technical Lead | Prioritized backlog with clear acceptance criteria |
| Architecture, dependency, and security planning (Planning) | Technical Lead | Developers, Security/Compliance, Engineering Manager | Technical approach and risk controls captured in plan/risk register |
| Sprint delivery, testing, and progress tracking (Execution) | Developers, Project Manager | QA/Test Engineer, Technical Lead, Product Manager, Engineering Manager | Demo-ready increments, updated board, current risk/status updates |
| Risk, blocker, and escalation management (Execution) | Project Manager | Technical Lead, Engineering Manager, Sponsor, Security/Compliance (as needed) | Decision log updates and escalated blockers with owners |
| Release readiness checks and go/no-go (Release) | Project Manager, Technical Lead | QA/Test Engineer, Security/Compliance, Support/Ops, Product Manager | Release checklist completion, sign-off inputs, and launch plan |
| Deployment communications and operational handoff (Release) | Project Manager, Support/Ops | Stakeholder/Sponsor, Product Manager, Developers | Stakeholder/support announcement and post-deploy monitoring plan |
| Retrospective and action prioritization (Retrospective) | Project Manager | Entire delivery team, Support/Ops, Data Analyst, Sponsor (for strategic actions) | Action items with owners, due dates, and success criteria |
| Continuous improvement follow-through (Ongoing) | Project Manager, Engineering Manager, Product Manager | Technical Lead, QA/Test Engineer, Data Analyst, Support/Ops | Verified completion of improvement actions and measured impact |

## Quick accountability prompts
- Who approves scope or timeline shifts?
- Who owns quality sign-off and who validates release readiness?
- Who receives customer-impact updates during incidents?
- Which actions from the last retrospective are still open, and who owns them?
